Shader 函数式心智模型

把每个 shader stage 看成大量并行调用的同一个函数。先找输入，再找变换，最后找输出。

vertex  : 顶点数据 × uniforms → 裁剪空间位置 × 插值数据
fragment: 插值数据 × textures × uniforms → 颜色 / 深度 / discard
compute : invocation id × resources → storage 写入

阅读顺序

问题WGSL / WESL 线索函数式类比
入口在哪里？@vertex、@fragment、@compute被运行时调用的顶层函数
每次调用的参数？函数参数、@location、@builtin显式参数
所有调用共享什么？@group / @binding、uniform、texture、sampler只读环境或闭包捕获
产出什么？返回类型、@location(0)、storage 写入返回值或受控副作用

绑定资源也是输入

资源函数式类比常见职责
texture只读数据源保存图像或其他可采样数据
sampler读取策略规定过滤和越界寻址方式
uniform只读配置提供一次 draw 中共享的小型参数

Texture / Sampler / textureSample

textureSample(texture_data, read_policy, normalized_uv) → vec4<f32>
对象职责当前全屏材质
texture_2d<f32>二维颜色数据screen_texture，来自 post-process source texture
sampler越界寻址与 texel 过滤策略默认 ClampToEdge + Nearest
uv归一化采样地址来自全屏 vertex shader 的 @location(0)

改颜色是后处理；改 UV 是改“从哪里取色”。textureSample(screen_texture, texture_sampler, uv + offset) 会把别处的屏幕颜色拉到当前片元。

Mask 控制 UV 扭曲

distortion = direction × amount × mask
sample_uv = uv + distortion
color = textureSample(texture, sampler, sample_uv)

mask 不只控制 mix，也可以控制采样地址的偏移强度。通常用 uv 算 mask，描述当前片元是否属于效果区域；用 sample_uv 采样 texture，描述当前片元要从哪里取颜色。

径向波形 UV 扭曲

direction = normalize(aspect_correct(uv − center))
amount = radial_wave(uv, center, aspect, frequency, speed, time)
distortion = uv_direction × amount × mask × strength

方向、强度、作用域要拆开：方向回答往哪里取色，波形回答哪一圈最强，mask 回答哪里允许发生。中心点要用 max(distance, epsilon) 一类写法避免除以 0。

当前全屏 Pass 的 UV

位置UV常用判断
左上(0, 0)uv.x < 0.5 选择左半
右上(1, 0)uv.x >= 0.5 选择右半
左下(0, 1)uv.y >= 0.5 选择下半
右下(1, 1)同时满足右半与下半条件

用 Mask 组合效果

表达式含义典型用途
distance(uv, center)把二维位置变成标量距离圆形、光晕、暗角
smoothstep(a, b, x)把范围平滑映射到 0…1软边、渐变阈值
mix(A, B, mask)按 mask 在两个值间插值叠加、显隐、颜色过渡
位置 → 标量场 → 0…1 mask → mix(A, B, mask)
mix(A, B, t) = A × (1 − t) + B × t

宽屏中的径向距离

delta = uv − center
delta.x *= width / height
d = length(delta)

先居中再修正 x。圆形、光晕和径向暗角需要此修正；独立比较 x/y 范围的轴对齐矩形不需要。

Rust → Uniform → WESL

Rust value → ShaderType encoding → bind group → var<uniform> material
修改必须同步
增加 material 字段Rust 与 WESL 的字段顺序和对应类型
增加动态参数Rust 系统还要在运行时写入实际数值
改变尾部布局重新检查 uniform 对齐与 padding

GPU 按字节偏移读取，不认识 Rust 字段。布局不一致时可能读到隐式对齐空洞；若 shader 所需范围大于实际 buffer，通常会触发管线或绑定验证错误。

组件驱动 Shader

game state → effect component → sync system → uniform material → fragment
层职责
效果组件表达游戏希望出现的效果参数
同步系统结合 viewport 等渲染环境，把组件映射为 uniform
Material匹配 GPU uniform 的字段顺序、类型和布局
Shader对给定输入执行相同的并行颜色变换

时间驱动参数

time → sin(time × speed) → remap to 0…1 → lerp(min, max) → component

周期效果可直接写成 value = f(elapsed_time)；速度积分才通常使用 value += speed × delta_time。CPU 修改组件后，现有同步系统和 shader 无需因动画策略而改变。

CPU 动画还是 GPU 动画

输入范围通常放置原因
整个 draw 共享一个最终值CPU / 游戏系统只计算一次，状态控制直接
时间还要结合每个 fragment 的 UVGPU / shader每个 invocation 能产生不同空间相位
Rust wrapped time → uniform → fragment: value = f(time, uv)

时间 × 空间相位

d = length(aspect_correct(uv − center))
phase = d × frequency − time × speed
ring = sharpen(0.5 + 0.5 × sin(phase))

这是 GPU 动画的常见形状：时间是共享输入，距离或 UV 是每个 fragment 的局部输入。改变 frequency 会改变圆环密度；改变 speed 会改变运动速度。稳定后可以抽为 radial_wave(uv, center, aspect, frequency, speed, time) -> f32。

效果层组合

source_layer → target_layer
strength = shape_mask × gate_mask
output = mix(source_layer, target_layer, strength)

复杂效果不要只连续修改 color。先命名当前层、目标层和影响域；检查 strength = 0 与 strength = 1 时分别返回什么。

反向 Mask 与优先级

目标Gate含义
只影响亮区maskmask 高值区域允许效果进入
只影响暗区1.0 - mask保护原本的高值区域
只影响软边mask × (1.0 - mask) × 4.0中心和外侧都弱，过渡区最强

效果优先级通常不是单独的语法，而是通过 gate 保护某些区域：谁的区域先被排除，谁就不会被后续效果覆盖。

抽出 WESL Helper

helper(input values) → output value
root shader: import super::module::helper
current fork: Bevy loader tracks file_dependencies

优先抽出只依赖显式参数的纯 helper。这样 fragment 负责业务数据流，helper 负责稳定公式；当前项目使用的 Bevy fork 会自动加载 import 依赖，移植回旧 Bevy 时再检查是否需要手动强 handle。

参数归属

归属适合放什么例子
helper 内部公式固定部分sin(x) * 0.5 + 0.5
调用点当前 shader 的固定风格值radial_wave(..., 32.0, 6.0, time)
uniform一次 draw 共享、运行时可变的渲染参数elapsed_secs、ring_brightness
Rust 组件游戏侧表达的效果意图ScreenSpotlight.radius
component intent → sync system → uniform value → helper argument

不要为了“通用”把所有数字都提升为 uniform。每提升一个字段，都增加 Rust/WESL 布局契约和同步路径；优先提升需要被游戏侧配置或动画驱动的值。

类比边界：fragment 不是固定等于“一个屏幕像素”；光栅化、深度测试、MSAA 和 discard 都会改变实际调用或写入。不同 invocation 之间也没有可依赖的先后顺序。
