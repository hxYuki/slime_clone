Bevy Schedule 速查

基于本项目当前使用的 Bevy 0.19 git 源码整理。重点是 render schedule；同时列出主 App schedule 和 state/remote 等内置 schedule，方便区分“游戏逻辑顺序”和“渲染顺序”。

术语边界：Schedule 是系统运行的容器；SystemSet 是 schedule 内的排序分组。大多数 render 排序问题不是新增 schedule，而是在正确 schedule 里用 .in_set()、.after()、.before() 放对位置。

1. Main App schedules

这些运行在主世界，处理 gameplay、输入、状态、UI 数据等。渲染默认不在这里执行。

Startup 阶段：第一次 Main 执行时运行一次

StateTransition? → PreStartup → Startup → PostStartup
Schedule简介
Main主调度器 schedule；每次 App::update() 运行时按顺序调用子 schedules。
PreStartup启动前准备，运行在 Startup 之前。
Startup常规启动逻辑，只运行一次。
PostStartup启动后收尾，只运行一次。

每帧阶段：Main 每次更新都会按序运行

First → PreUpdate → StateTransition? → RunFixedMainLoop → Update → SpawnScene → PostUpdate → Last
Schedule简介
First每帧最早运行。
PreUpdate插件/引擎准备输入和消息等，让 Update 读取到整理后的数据。
RunFixedMainLoop按累计时间运行 FixedMain 零到多次。
Update常规每帧游戏逻辑、输入响应、UI 控制、音频控制。
SpawnScene场景实例生成，位于 Update 和 PostUpdate 之间。
PostUpdate对 Update 结果做引擎响应，例如 transform 同步。
Last每帧最后运行。

固定步长阶段

FixedMain = FixedFirst → FixedPreUpdate → FixedUpdate → FixedPostUpdate → FixedLast
Schedule简介
FixedMain固定 timestep 的主调度器。
FixedFirst固定步长最早阶段。
FixedPreUpdate固定逻辑前准备。
FixedUpdate固定频率游戏逻辑，适合物理、AI、规则、网络同步。
FixedPostUpdate固定逻辑后响应。
FixedLast固定步长最后阶段。

2. State schedules

启用 bevy_state 时存在，用于状态切换。

Schedule简介
StateTransition处理 NextState，默认在 startup 前和每帧 PreUpdate 后运行。
OnExit(S)离开某个状态时运行。
OnTransition { exited, entered }从指定状态切到指定状态时运行，位于 exit 和 enter 之间。
OnEnter(S)进入某个状态时运行。

3. Render schedules：真正渲染相关

渲染发生在 RenderApp 子应用中。主世界先跑游戏逻辑，再把数据 extract 到 render world，然后 render world 准备 GPU 资源并执行渲染。

Schedule层级简介
ExtractSchedulemain → render把主世界数据提取到 render world；应尽量短。
RenderStartupRenderApp初始化 GPU 资源；设备恢复时可能再次运行。
RenderRenderApp主 render schedule，包含准备资源、排队、排序、执行 render backend、cleanup。
RenderGraphroot render graph每帧由 render_system 驱动，负责执行 camera-driven schedules 并提交 command buffers。
Core2dcamera pipeline2D 相机渲染 schedule。当前项目 fullscreen effect 插在这里。
Core3dcamera pipeline3D 相机渲染 schedule。

RenderSystems：Render schedule 内的主要 sets

ExtractCommands → PrepareMeshes → CreateViews → Specialize → PrepareViews → Queue → PhaseSort → Prepare → Render → Cleanup → PostCleanup
SystemSet用途
ExtractCommands应用 ExtractSchedule 产生的 commands。
PrepareAssets处理本帧新增、修改、移除的 GPU assets。
PrepareMeshes准备提取出的 meshes。
CreateViews创建 shadow map 等额外 views。
Specialize按 view/material 等条件特化 pipeline。
PrepareViews准备相机和额外 view 相关资源。
Queue把可绘制实体排入 render phases。
QueueMeshesQueue 内的 mesh 排队子集。
QueueSweepQueue 内清理不可见或 phase 变化的项目。
PhaseSort排序 sorted phases / binned phases。
Prepare按排序结果准备 GPU 资源和 bind groups。
PrepareResourcesPrepare 内初始化 buffers、textures、uniforms。
PrepareResourcesBatchPhases为 render phases 创建 batches。
PrepareResourcesWritePhaseBuffers把 phase batches 写入 GPU。
PrepareResourcesCollectPhaseBuffers收集 phase buffers。
PrepareResourcesFlushflush buffers，位于资源准备和 bind group 准备之间。
PrepareBindGroups创建依赖 GPU 资源的 bind groups。
Render实际调用 render backend。
Cleanup清理 render 资源。
PostCleanup最终清理临时 render entities。

RenderGraphSystems：RenderGraph schedule 内的 sets

Begin → Render → Submit → Finish
SystemSet用途
Begin每帧渲染前准备。
Render主渲染阶段；CorePipeline 的 camera driver 在这里执行 camera schedules。
Submit提交渲染阶段生成的 command buffers。
Finish提交后收尾。

Core2d/Core3d camera schedule sets

Prepass → MainPass → EarlyPostProcess → PostProcess
SystemSet2D/3D 含义
Prepass预处理 pass，例如 3D depth prepass。
MainPass主绘制 pass：2D sprites/meshes 或 3D opaque/transparent。
EarlyPostProcess早期后处理。
PostProcess常规后处理。

4. 常用内置 pass / system 名称

下面这些不是新的 schedule，而是已经被 Bevy 插到 Core2d / Core3d 里的 system。自定义 fullscreen pass 时，通常用它们做 .before(...) / .after(...) 锚点。

注意：部分 pass 来自可选插件或 feature，例如 bevy_post_process、bevy_anti_alias、bevy_pbr。表中列的是本地 Bevy 0.19 源码中的常见内置锚点，不表示当前项目一定启用了每一个效果。

2D 常用 pass

System所在位置用途排序用途
main_opaque_pass_2dCore2dSystems::MainPass绘制 2D opaque phase。很少直接锚定；通常只需知道它早于 post-process。
main_transparent_pass_2dCore2dSystems::MainPass绘制 2D transparent phase，sprites/UI 之外的 2D 透明绘制主要在这里。需要在 2D 主画面完成后处理时，排到 MainPass 之后。
bloomCore2dSystems::PostProcess泛光；Bevy 将其放在 tonemapping 之前。HDR 空间效果通常放在 tonemapping 前。
post_processingCore2dBevy post-process effect stack。源码中排在 bloom 后、tonemapping 前。
tonemappingCore2dSystems::PostProcess把 HDR/线性颜色映射到显示用颜色范围。决定效果是在 tonemap 前还是 tonemap 后运行。
fxaaCore2dSystems::PostProcessFast Approximate Anti-Aliasing。源码中排在 tonemapping 后。
smaaCore2dSystems::PostProcessSubpixel Morphological Anti-Aliasing。源码中排在 tonemapping 后。
casCore2dSystems::PostProcessContrast Adaptive Sharpening。源码中排在 fxaa / smaa 后。
ui_passCore2d把 UI phase 绘制到当前 ViewTarget。后处理要影响 UI，就排在它之后。
upscalingCore2d把 ViewTarget main texture blit 到最终输出 attachment。后处理要显示到窗口，就排在它之前。
msaa_writebackCore2dMSAA writeback。源码中排在 MainPass 前；普通 fullscreen effect 通常不锚定它。

常见排序模板

目标推荐排序说明
影响 2D 场景，不影响 UI.in_set(Core2dSystems::PostProcess).before(ui_pass)UI 后画上去，不会被处理。
影响 2D 场景 + UI.after(ui_pass).before(upscaling)当前项目正在使用的模式。
HDR 后处理.before(tonemapping)适合 bloom、曝光、部分颜色空间相关效果。
LDR/display 后处理.after(tonemapping)适合 FXAA/SMAA、屏幕空间像素风格效果。
最终窗口前处理.before(upscaling)不要放到 upscaling 后面。

5. fullscreen post-process 位置

这部分是 post-process 专题的速查。后续 shader 主线会优先使用普通 Material2d / Material3d；只有需要处理整张屏幕输出时才回到这里。

Bevy 0.19 中，UI pass 被加入 Core2d / Core3d，排序是：

ui_pass
    .after(Core2dSystems::PostProcess)
    .before(upscaling)

因此当前项目如果要让 shader 同时影响场景和 UI，并且显示到窗口，应使用：

system
    .after(ui_render::ui_pass)
    .before(core_pipeline::upscaling::upscaling)
位置实验现象原因
before(ui_pass)UI 不受影响；聚光外黑色/闪背景。UI 尚未写入 source texture，之后 UI 又被画上去。
after(ui_pass).before(upscaling)效果作用于 UI + 场景并显示。读取最终 UI-inclusive main texture，写回 ViewTarget，再由 upscaling 输出。
after(upscaling)效果不显示。窗口输出已经完成，后续写 ViewTarget 内部 texture 错过 present 路径。

6. 其他内置 schedule

Schedule来源简介
RemoteLastbevy_remote处理 Bevy Remote Protocol 请求的 schedule；仅在相关插件启用时使用。
RenderRecoverybevy_render内部 schedule，用于设备恢复时运行 render schedule order；源码中为私有类型，通常不直接使用。
DefaultSchedulebevy_ecsSchedule::default() 的内部默认 label；业务代码不应依赖。

7. 判断 checklist

问题看哪里
系统修改 gameplay 数据？主 App schedule：通常 Update 或 PostUpdate。
系统把主世界数据传给渲染？ExtractSchedule。
系统准备 GPU pipeline / bind group？Render schedule 的 Prepare / PrepareBindGroups。
系统是一道屏幕后处理？Core2d / Core3d camera schedule。
后处理要影响 UI？排在 ui_pass 之后。
后处理要显示到窗口？排在 upscaling 之前。
