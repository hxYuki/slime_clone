Lesson 0026 · Render Schedule

Render Schedule 决定 Fullscreen Pass 看见什么、影响什么

同一段 shader 代码，放在 UI 之前、UI 之后、upscaling 之后，结果完全不同。本课把这次实验收束成一个可复用的判断规则。

本课胜利条件：能解释为什么当前 fullscreen effect 必须放在 ui_pass 之后、upscaling 之前。

1. 当前项目的正确顺序

fn schedule() -> impl ScheduleLabel + Clone {
    bevy::core_pipeline::Core2d
}

fn schedule_configs(system: ScheduleConfigs<BoxedSystem>) -> ScheduleConfigs<BoxedSystem> {
    system
        .after(ui_render::ui_pass)
        .before(core_pipeline::upscaling::upscaling)
}

这不是任意写法。它明确要求当前 pass 位于 UI 绘制之后、最终输出之前。

2D main pass / post process ↓ ui_pass ↓ RegionColorScreenMaterial fullscreen pass ↓ upscaling ↓ window output

2. FullscreenMaterial 实际做了什么

Bevy 的 FullscreenMaterialPlugin 会把你的 material 系统插入你指定的 schedule。系统内部通过 ViewTarget::post_process_write() 拿到一对 texture：

角色含义
source当前已经渲染好的上一张 ViewTarget texture，shader 从这里读。
destination本 pass 要写入的下一张 ViewTarget texture。

所以 fullscreen pass 本质是一次“读旧屏幕 → 写新屏幕”的后处理。它读到什么，完全取决于它之前已经有哪些 pass 写过。

3. 实验 A：放在 UI 之前

system.before(ui_render::ui_pass)

观察结果：聚光范围外是黑色，并快速闪出原本背景；UI 不受影响。

解释：fullscreen pass 运行时，UI 还没有画入 source texture。之后 ui_pass 会再画一次 UI，所以 UI 看起来没有被 shader 处理。

判断规则：如果一个后处理要影响 UI，它必须排在 UI 绘制之后。

4. 实验 B：放在 upscaling 之后

system.after(core_pipeline::upscaling::upscaling)

观察结果：整个效果都不会显示。

解释：upscaling 已经把 ViewTarget.main_texture_view() blit 到窗口输出。之后 fullscreen pass 即使继续写 ViewTarget 的内部 texture，也已经错过了本帧最终呈现的位置。

判断规则：如果一个后处理要显示到窗口，它必须排在最终输出 pass 之前。

5. Render schedule 的分层

这里容易混淆：Render、RenderGraph、Core2d 都是 schedule，但它们处在不同层。

层级Schedule职责
Main AppMain / Update / PostUpdate游戏逻辑、输入、状态、UI 数据变化。
ExtractExtractSchedule把主世界数据复制到 render world。
RenderAppRender准备 GPU 资源、排队 draw items、运行 render backend。
Root render graphRenderGraph驱动每帧的渲染图与 camera schedules。
Camera pipelineCore2d / Core3d真正按相机执行 main pass、postprocess、UI、upscaling。

6. 本项目的实用结论

当前效果是“作用于最终 2D + UI 画面，但在窗口输出前处理”。因此位置应保持：

system
    .after(ui_render::ui_pass)
    .before(core_pipeline::upscaling::upscaling)

如果之后要做真正 two-pass blur，可以继续在 Core2d 里添加第二个 fullscreen pass，关键是明确 pass 1 的输出如何成为 pass 2 的输入，而不是只在同一个 shader 里写两个 helper。

如果一个 fullscreen post-process 要影响 UI，应该放在哪里？
