Lesson 0019 · Parameter Ownership

决定参数归属

抽出 helper 后，下一件事不是把所有数字都变成 uniform。先判断：这个数字由谁负责？公式、调用点、uniform，还是游戏组件？

本课胜利条件：把圆环亮度 0.12 提升为 ScreenSpotlight 驱动的 uniform，同时保留 frequency 与 speed 作为调用点常量。

1. 四种归属

放置位置判断标准本项目例子
helper 内部公式的一部分，调用者通常不该改sin(x) * 0.5 + 0.5 的归一化
调用点字面量这个 shader 的固定风格，暂时不需要游戏侧配置radial_wave(..., 32.0, 6.0, time)
uniform 字段一次 draw 共享，但可能随相机、材质或时间变化spotlight_radius、elapsed_secs
Rust 组件游戏侧希望表达的效果意图ScreenSpotlight.center、radius
game intent → component → sync system → uniform → shader helper arguments

helper 仍然保持纯函数：它不直接读取 material。fragment 负责把 uniform 和局部输入整理成 helper 参数。

2. 为什么这次只提升 ring_brightness

ring * 0.12 控制圆环有多亮，是明显的视觉风格参数。它适合被标题相机或不同关卡配置，所以可以进入 ScreenSpotlight。

32.0 与 6.0 分别控制波纹密度和速度。它们也可以提升，但本课先只移动一个字段；每次只改变一个归属，才容易验证画面和 uniform 布局。

3. 这次替换 padding，不追加字段

// Rust: RegionColorScreenMaterial 尾部
spotlight_center: Vec2,
elapsed_secs: f32,
ring_brightness: f32, // 替换 _padding: f32

// WESL: RegionColorScreenMaterial 尾部
spotlight_center: vec2<f32>,
elapsed_secs: f32,
ring_brightness: f32, // 替换 _padding: f32

当前尾部 _padding: f32 本来只是占位。用同类型字段替换它，字段偏移和总大小应保持不变；如果追加在后面，反而会扩大 uniform 结构。

4. 数据流应该变成这样

// src/region_color_screen_material.rs
pub struct ScreenSpotlight {
    pub center: Vec2,
    pub radius: f32,
    pub softness: f32,
    pub ring_brightness: f32,
}

screen_material.ring_brightness = spotlight.ring_brightness;
// assets/shaders/region_color_screen_material.wesl
let ringed_color = add_masked_rgb(
    lit_color,
    ring * material.ring_brightness,
    ring_strength,
);
判断规则：能被游戏设计调的值，优先从组件进入；只影响当前公式形状、且暂时没有配置需求的值，先留在调用点。不要为了“看起来更通用”把所有数字都提升。
ring_brightness 应该属于哪一层？

本课为什么不先把 frequency/speed 也提升？

实际编码：
  1. 给 ScreenSpotlight 增加 ring_brightness: f32，默认值设为 0.12。
  2. 在 spawn_camera 的 ScreenSpotlight 字面量中补上 ring_brightness: 0.12；想看明显变化时可临时改到 0.2。
  3. 把 Rust 与 WESL material 里的 _padding: f32 都替换为 ring_brightness: f32。
  4. 在同步系统里写入 screen_material.ring_brightness = spotlight.ring_brightness。
  5. 把 ring * 0.12 改为 ring * material.ring_brightness。
  6. 运行游戏确认效果可调；完成后告诉我“已完成”。
