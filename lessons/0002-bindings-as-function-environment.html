Binding 是函数的外部环境

你已经能追踪主数据流。本课只补一个关键缺口：没有写进入口函数参数列表的资源，仍然是 shader 的输入。

你的注释“textureSample 的参数都是输入”是对的——它们是该次采样调用的输入。对整个 fragment 而言，后面读取的 material 也同样属于输入。

1. 把隐藏环境写成伪函数

// WESL 表面形式
fragment(in) -> color

// 更完整的函数式心智模型
fragment(
    in,
    environment {
        screen_texture,
        texture_sampler,
        material
    }
) -> color

@group / @binding 声明由 CPU/Bevy 在运行前连接资源。它们很像闭包捕获的只读环境：没有出现在参数列表里，但函数计算依赖它们。

2. 给当前标识符分类

类别当前 shader作用
每次 invocation 的输入in.uv本次 fragment 对应的采样位置
绑定资源screen_texture保存待采样的屏幕图像数据
绑定资源texture_sampler规定过滤和越界寻址等采样方式
uniform 输入material提供矩形数量、范围和颜色参数
局部中间值color、i、r只服务于当前 invocation 的计算
输出return color写向 @location(0) 对应的颜色目标

3. Texture 与 Sampler 为什么分开？

textureSample(screen_texture, texture_sampler, in.uv)
              // 数据         // 读取规则       // 位置

同一张 texture 可以搭配不同 sampler：例如最近邻或线性过滤。函数式地看，textureSample 需要“数据、读取规则、坐标”三个输入才能产生颜色。
