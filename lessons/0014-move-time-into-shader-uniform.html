Lesson 0014 · CPU vs GPU

把时间传入 Shader

上一课由 CPU 计算最终半径。本课只传递时间，让每个 fragment invocation 在 GPU 上计算同一个呼吸公式，从而看清“动画逻辑放在哪里”的取舍。

本课胜利条件：删除标题侧半径动画系统；画面仍按相同范围和两秒周期呼吸，动画公式改由 WESL 执行。

1. 两种位置，没有绝对优劣

位置优点适合
CPU共享标量只计算一次；容易受游戏状态控制一个半径、一个透明度、玩法动画
GPU每个 invocation 可结合自己的 UV、距离或噪声波纹、扫描线、扭曲、逐像素相位
严格来说：当前“全屏共享一个半径”的计算放在 CPU 更便宜。本课迁移到 GPU 是为了学习时间 uniform；下一课加入空间相位后，GPU 方案才会发挥真正价值。

2. 用 Padding 容纳时间

// Rust 与 WESL 同步替换
spotlight_center: Vec2 / vec2<f32>,
elapsed_seconds: f32,
_padding: f32,

原来的尾部是一个 8 字节 Vec2 padding。现在改成两个连续的 4 字节标量：一个存时间，一个继续 padding。结构总大小仍为 560 字节。

3. Rust 只传递时钟

fn sync_greyout_regions_to_screen_material(
    time: Res<Time>,
    // 原有 query...
) {
    // 原有同步...
    screen_material.elapsed_seconds = time.elapsed_secs_wrapped();
}

elapsed_secs_wrapped() 会周期性回绕，避免持续增长的 f32 时间逐渐丢失精度；Bevy 文档明确把 shader 列为它的使用场景。

4. WESL 计算半径

let pulse = sin(material.elapsed_seconds * 3.14159265) * 0.06;
let animated_radius = material.spotlight_radius + pulse;

let spotlight_mask = circular_mask(
    in.uv,
    material.spotlight_center,
    animated_radius,
    material.spotlight_softness,
    material.ratio,
);

基础半径仍来自 ScreenSpotlight。时间频率为 π 弧度/秒，所以周期为两秒；振幅 0.06 让 0.22 在 0.16..0.28 间变化。
