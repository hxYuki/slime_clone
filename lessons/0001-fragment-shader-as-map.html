把 Fragment Shader 当作 map

本课服务于一个具体目标：读懂项目现有的全屏效果，并能预测一次代码修改会怎样改变画面。

本课胜利条件：看到一个 fragment 入口函数时，能指出它的输入、变换和输出。

1. 可用的函数式模型

对当前全屏效果，可以先把 GPU 想成对光栅化产生的每个 fragment 并行调用同一个函数：

fragment : (uv, screen_texture, material) -> color
用 UV 采样
原屏幕颜色
→
根据矩形与参数
变换颜色
→
返回新的
目标颜色

纹理和 uniform 没写在函数参数中，但可把它们看成函数捕获的只读环境。重要的是：每次调用运行相同代码，输入值不同。

2. 用这个模型读项目代码

// 输入：插值后的 UV；共享环境：纹理、采样器、material
@fragment
fn fragment(in: FullscreenVertexOutput) -> @location(0) vec4<f32> {
    // 取值
    var color = textureSample(screen_texture, texture_sampler, in.uv);

    // 变换
    if inside_greyout_rect(in.uv) {
        color *= material.color;
    }

    // 输出
    return color;
}

实际代码用循环检查多个矩形，但核心仍是 sample → transform → return。它不是按顺序编辑整张图片；许多 fragment invocation 会并行计算各自的返回值。
